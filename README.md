## 🧭 About

I'm a Senior Backend Engineer & Software Architect based in Cairo, Egypt, with 7+ years in PHP/Laravel. I've spent that time on both sides of the fence — building enterprise-scale systems at places like **Spryker**, **Actindo**, **IHF**, and the **Islamic Development Bank**, and architecting my own products solo from scratch.

## 📖 Pick a bedtime story

<details>
<summary><b>🚕 The one about the mobility platform I built alone</b></summary>
<br>

**SinaiTaxi** is a mobility platform I solo-architected as a 35-module modular monolith, using Domain-Driven Design and hexagonal architecture.

Inside it:
- A **geo-polygon pricing engine** — pricing that actually understands geography, not just distance
- A **multi-party financial settlement engine** — splitting money correctly between drivers, partners, and the platform, every time
- A **pluggable OTA connector framework** — so integrating a new booking partner doesn't mean rewriting core logic
- A **Pest PHP test suite wired into CI/CD**, because architecture without tests is just a nice diagram

It's the project I point to when someone asks "okay, but have you actually *owned* something end to end?"

</details>

<details>
<summary><b>🧩 The one about teaching APIs to describe their own workflows</b></summary>
<br>

**php-arazzo** is a PHP package implementing the [Arazzo Specification](https://github.com/OAI/Arazzo-Specification) — the OpenAPI Initiative's format for describing multi-step API workflows.

It's not just a parser/validator — it includes a workflow **executor/runner**, so an Arazzo document doesn't just describe a workflow, it can actually *run* one. I built this after working on a process orchestration engine (places/actions/tokens) at Actindo, and I'm now coordinating with maintainers in the wider Arazzo ecosystem on test suites and tooling.

</details>

<details>
